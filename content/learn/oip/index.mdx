## Overview

The Observation and Incentive Protocol (OIP) pays gateways for serving data well. Gateways check on each other: each [epoch](/learn/oip/epoch-pipeline) (24 hours on mainnet), up to 50 gateways are chosen as [observers](/glossary#observer) and test every gateway. Gateways that pass earn ARIO. Gateways that fail earn no gateway reward for that epoch, and a gateway that fails 30 epochs in a row can be [pruned](/learn/oip/pruning).

## How an epoch works

No central server runs the protocol or sends notifications. [Crankers](/glossary#cranker), which can be any wallet with SOL, move each epoch forward. Each observer reads the current epoch on Solana to learn whether it was chosen and which names to test.

```mermaid
sequenceDiagram
    accTitle: Observers test every gateway, and the protocol pays the gateways that most observers passed
    accDescr: At the start of an epoch a cranker asks the gateway registry program on Solana to pick up to 50 observers and up to 2 shared ArNS names. Each chosen observer reads that assignment and asks every gateway to resolve the shared names plus some names it picks itself. It compares each answer with trusted reference gateways and marks the gateway pass or fail. Before the epoch ends it uploads its full report to Arweave and submits a pass or fail result for each gateway, plus the report's transaction ID. After the epoch ends a cranker triggers payout. A gateway fails if more than half of the submitted reports failed it. Passing gateways, and gateways whose observers reported, get their rewards added to stake.

    participant CR as Cranker
    participant GAR as Gateway registry on Solana
    participant OBS as Observer
    participant GW as Other gateways
    participant AR as Arweave

    Note over CR,AR: Epoch start
    CR->>GAR: Start epoch, pick observers and names
    OBS->>GAR: Read the epoch
    GAR-->>OBS: Chosen observers and names
    Note over CR,AR: Observation
    loop Every active gateway
        OBS->>GW: Resolve shared and own ArNS names
        GW-->>OBS: Resolved tx ID and data
        Note over OBS: Compare with reference gateways, mark pass or fail
    end
    Note over CR,AR: Reporting, before the epoch ends
    OBS->>AR: Upload full report
    AR-->>OBS: Report tx ID
    OBS->>GAR: Pass or fail per gateway and report tx ID
    Note over CR,AR: After the epoch ends
    CR->>GAR: Pay out the epoch
    Note over GAR: Fail gateways that more than half of reports failed
    Note over GAR: Add rewards to stake of passing gateways and reporting observers
```

Observers pay SOL to submit their results, so an observer wallet needs SOL. Every report stays on Arweave, and you can browse current observers and results at [gateways.ar.io](https://gateways.ar.io). ArNS name fees and other protocol fees fund the [protocol balance](/glossary#protocol-balance) that pays the rewards. For the transactions behind each step, see [Epoch pipeline](/learn/oip/epoch-pipeline).

## What observers check

Observers test whether each gateway can:

- Resolve ArNS names to the same transaction ID, cache time (TTL), and content type that reference gateways return
- Return the same data, compared by its hash
- Serve Arweave data by its position on the chain (its offset), with proof that it matches the chain

Observers can change how they test without a change to the protocol.
