You own your ANT outright, so everything on this page is you exercising that ownership. None of it costs Turbo Credits — Turbo sponsors the Solana fees and rent.

## Resolution records

`set-record` points a name (or an undername) at an Arweave transaction; `remove-record` deletes one.

```typescript
// Point the apex '@' record at some data
await post('/v1/arns/actions/set-record', {
  antId,
  ownerAddress: solanaPublicKey,
  transactionId: arweaveTxId,
  undername: '@',      // omit for the apex record
  ttlSeconds: 900,
});

await post('/v1/arns/actions/remove-record', { antId, ownerAddress, undername: 'docs' });
```

These are the two actions whose shape depends on state. **While Turbo is a controller of your ANT, they return `completed` immediately** — Turbo already holds the authority to write. If you have not added Turbo as a controller, or you revoked it, the same call returns `awaiting-signature` and you sign it yourself. Handle both; do not assume one.

### Proving you own the ANT

Record actions carry **two** signatures, because two different things are being authorized: your Turbo identity is making the request, and the ANT's owner is permitting it.

The payer's signed request uses the usual `x-signature` / `x-public-key` / `x-nonce` headers. The owner's proof uses a parallel `x-owner-*` set:

| Header | Purpose |
|---|---|
| `x-owner-signature` | the ANT owner's action-bound signature |
| `x-owner-public-key` | the owner's public key |
| `x-owner-nonce` | single-use nonce |
| `x-owner-signature-type` | signature scheme |

The signature is bound to the exact action and its fields, and the nonce is consumed on use — so a signature captured from one request cannot authorize a different one, or replay the same one to revert a record to an older value. Legitimate retries use a fresh nonce.

Turbo then checks that the signer is the ANT's **current on-chain owner**. Ownership is read from the chain rather than from a table Turbo maintains, which is why this works for an ANT Turbo has never held.

## Controllers

A controller may write records but may not transfer or sell the ANT. Adding Turbo as one is what makes `set-record` a single call.

```typescript
// Let Turbo manage records for you. Omit `target` for Turbo's own signer.
await post('/v1/arns/actions/add-controller', { antId, ownerAddress });

// Revoke it. Always free, always available.
await post('/v1/arns/actions/remove-controller', { antId, ownerAddress });
```

Both require your signature, because changing an ANT's access control is an owner-only instruction.

<Callout type="info">
  **Revocation is the point.** `remove-controller` costs nothing and needs no
  cooperation from Turbo beyond paying the fee. Being able to revoke at any
  time, unilaterally, is what makes "you own the ANT" a fact rather than a
  promise.
</Callout>

## Transfer

Hands the ANT to a new owner. This is a real change of ownership: after it lands, your key no longer controls the name.

```typescript
await post('/v1/arns/actions/transfer', {
  antId,
  ownerAddress: currentSolanaPublicKey,
  target: newSolanaPublicKey,
});
```

Owner-signed, and sponsored by Turbo like the rest.
