description: "SDK for interacting with Turbo, a fast and efficient data upload service for Arweave"

Every ArNS operation paid for with Turbo Credits — buying, extending, upgrading, managing records, changing controllers, transferring — is an **action**, and every action goes through one endpoint:

```
POST /v1/arns/actions/{action}      create an action
POST /v1/arns/actions/{nonce}/sign  return the signed transaction
GET  /v1/arns/actions/{nonce}       status
```

<Callout type="info">
  **Availability.** Use `@ardrive/turbo-sdk@1.42.0-alpha.11` or newer — the
  actions API is published on the **alpha** channel
  (`npm i @ardrive/turbo-sdk@alpha`). Earlier releases call routes that no
  longer exist and return `404`.
</Callout>

## An action has one of two shapes

The response tells you which — you never choose it:

```jsonc
// Turbo already held the authority. Nothing left to do.
{ "nonce": "…", "action": "set-record", "status": "completed",
  "antId": "…", "messageId": "…" }

// Only the ANT's owner can authorize this.
{ "nonce": "…", "action": "buy-name", "status": "awaiting-signature",
  "transaction": "<base64, already signed by Turbo as fee payer>",
  "lastValidBlockHeight": "…", "expiresAt": "…" }
```

**The SDK handles this for you.** Each action is one call, and the branch is
internal:

```typescript
import { TurboFactory, solanaOwnerSigner } from '@ardrive/turbo-sdk';

const turbo = TurboFactory.authenticated({ privateKey: payerKey });
const { antId, messageId } = await turbo.buyArNSName({
  name: 'my-name',
  owner,                 // an ArNSOwnerSigner — see "Connecting a signer"
  type: 'lease',
  years: 1,
});
```

If you drive the HTTP surface directly instead, the branch is yours to handle,
and it is the same handful of lines for every action:

```typescript
let res = await turbo.createArNSAction(action, params);

if (res.status === 'awaiting-signature') {
  res = await turbo.signArNSAction(
    res.nonce,
    await owner.signTransaction(res.transaction),
  );
}
// res.status === 'completed', res.messageId is the on-chain write
```

<Callout type="info">
  **Sign the bytes Turbo returned — never rebuild the transaction.** Turbo has
  already signed it as fee payer, and that signature covers exactly the bytes
  in the response. A reconstructed message will not match and will be rejected.
</Callout>

## Why the shape is not fixed per action

`set-record` completes in one call while Turbo is a controller of your ANT, and requires your signature the moment you revoke us. The caller cannot know which is true; the server can, and it degrades gracefully instead of erroring.

## Which actions need your signature

| Action | Costs credits | Your signature |
|---|---|---|
| `buy-name` | yes | **once**, at mint |
| `extend-lease` | yes | no |
| `upgrade-name` | yes | no |
| `increase-undername-limit` | yes | no |
| `set-record` | no | only if Turbo is not a controller |
| `remove-record` | no | only if Turbo is not a controller |
| `add-controller` | no | yes |
| `remove-controller` | no | yes |
| `transfer` | no | yes |
| `set-record-metadata` | no | only if Turbo is not a controller |
| `remove-record-metadata` | no | only if Turbo is not a controller |
| `transfer-record` | no | only if Turbo is not a controller |

`buy-name` is the only action that *always* needs a signature, because minting the ANT is the one instruction in the whole lifecycle that requires the owner's key. You sign once, at purchase, and never again for the life of the name — unless you exercise ownership by changing controllers or transferring it.

Only the four purchase actions debit credits. Record, metadata, controller and transfer actions are free: Turbo sponsors the Solana fees and rent.

<Callout type="warn">
  **Sponsorship covers these twelve actions and nothing else.** Turbo pays the
  Solana fees and rent only for the operations listed above. Everything else
  in the ArNS and ANT programs stays on the direct-signer path via
  [`@ar.io/sdk`](https://github.com/ar-io/ar-io-sdk), where the user signs and
  **pays their own SOL**. That includes, at minimum:

  - **Buying a returned name** (`BuyReturnedName`) — the auction path. Turbo
    can *price* an auction but cannot buy one for you.
  - **Claiming a reserved name** (`ClaimReservedName`).
  - **Primary names** — the whole `RequestPrimaryName` /
    `RequestAndSetPrimaryName` / `RemovePrimaryName` flow, which lives in the
    ario core program rather than ArNS.
  - **Releasing or reassigning a name** (`ReleaseName`, `ReassignName`).
  - **ANT-level metadata**: the ANT's own name, ticker, description, keywords
    and logo. Note this is distinct from RECORD-level metadata, which
    `set-record-metadata` **does** sponsor.

  Buying a name and setting a primary name are both common, so scope the claim
  in your UI to the sponsored actions rather than promising a name can be
  managed end to end without SOL.
</Callout>

## The nonce

Every action is identified by a **UUID `nonce`** returned on the create call. It is the idempotency key, the argument to `/sign`, and the status-lookup key.

An action is **terminal-success** once its status carries a `messageId`, and **terminal-failure** once it carries a `failedDate`.

```
POST /v1/arns/actions/buy-name ──▶ { nonce, status: 'awaiting-signature', transaction }
                                        │
                       sign the bytes, POST …/{nonce}/sign
                                        │
       ┌────────────────────────────────┴────────────────────────────┐
  messageId present (success)                        failedDate present (failure)
```
