## Responses to expect

- **`402`** — the wallet (or delegated payer) doesn't hold enough Turbo Credits. Prompt a top-up, then create a fresh action. In the SDK this surfaces as `InsufficientCreditsError`, exported from the package root with `.status === 402`.
- **`400`** — the request is malformed or the chain rejected it: a missing per-intent field, a malformed Solana address, a name that fails validation, an out-of-range TTL, or an on-chain program error such as attempting to remove the apex record. These are terminal — retrying the same request unchanged will fail the same way.
- **`401`** — the signed request is missing or invalid, or, on a record action, the owner proof did not come from the ANT's current on-chain owner.
- **`409` / expiry** — a prepared transaction was not signed in time. Prepared transactions carry `expiresAt` and `lastValidBlockHeight`; past those, create a new action rather than submitting stale bytes.
- **`503`** — Turbo could not reach the chain. Safe to retry with the same nonce.

## Retry guidance

The `nonce` is the idempotency key. **Capture it from the create response before doing anything else.** If the network drops mid-flight, read `GET /v1/arns/actions/{nonce}` rather than re-issuing the action — a blind retry of a purchase risks paying twice for the same name.

Distinguish the two failures that look alike:

- **The action was never created** — nothing was charged; create it again.
- **The action exists but you lost the response** — poll it to a terminal state. If it is `awaiting-signature` and unexpired, resume by signing and calling `/sign`.

```typescript
try {
  const created = await post('/v1/arns/actions/buy-name', {
    name, type: 'permabuy', ownerAddress,
  });
  // persist created.nonce before signing — it is the only handle on this action
} catch (err) {
  if (err.status === 402) {
    // surface a top-up flow to the user
  } else {
    throw err;
  }
}
```

<Callout type="info">
  **Sign the exact bytes Turbo returned.** Turbo's fee-payer signature covers
  the transaction as sent. Rebuilding or re-serializing the message
  invalidates it, and `/sign` will reject the result.
</Callout>
